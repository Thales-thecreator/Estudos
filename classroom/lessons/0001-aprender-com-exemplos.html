Você já usa isso todo dia

O filtro de spam do seu e-mail, as palavras que o teclado do celular sugere, as recomendações da Netflix. Ninguém escreveu à mão uma regra para cada mensagem, cada palavra ou cada filme. Esses programas aprenderam olhando muitos exemplos.

Isso é Machine Learning (em português, aprendizado de máquina).

A ideia numa frase

Machine Learning é treinar um programa, chamado modelo, para fazer previsões úteis ou criar conteúdo (textos, imagens) a partir de dados.

Tradução livre da definição do curso de ML do Google.

A diferença para a programação comum está em quem escreve as regras:

Programação comum Regras (uma pessoa escreve) + dados → Programa → Respostas
Machine Learning Dados + respostas → Treino → Modelo (as regras)

Em vez de alguém escrever as regras, você dá ao computador exemplos com a resposta certa, e ele descobre o padrão sozinho. Como alguém precisa marcar as respostas certas, como um supervisor, esse tipo de ML se chama aprendizado supervisionado. (Elements of AI, cap. 4.1)

O que acabou de acontecer

Você não recebeu nenhuma regra. Olhou exemplos com resposta e montou uma regra na cabeça, algo como “promete dinheiro → spam”. Depois usou essa regra em mensagens que nunca tinha visto. Estes são os nomes de cada parte, que vamos usar daqui em diante:

Dados
os exemplos (as 6 mensagens).
Rótulo
a resposta certa de cada exemplo (spam ou não spam).
Treino
olhar os exemplos e descobrir o padrão.
Modelo
a regra descoberta no treino.
Previsão
a resposta do modelo para um caso novo.

Em inglês, que você vai ler muito: dataset, label, training, model, prediction (como no curso do Google).

Duas coisas para guardar

  1. ML vale a pena quando a regra é difícil de escrever. Prever chuva escrevendo equações de física é dificílimo; é mais viável dar ao modelo muitos dados de clima e deixar que ele aprenda a relação. (Google) Se a regra é simples e conhecida, como uma tabela de imposto, é só escrever a regra.
  2. O modelo só sabe o que os exemplos mostraram. Exemplos ruins ou incompletos geram um modelo que erra, como você viu na mensagem do salário. Por isso, boa parte do trabalho de um ML Engineer é cuidar dos dados e medir onde o modelo erra.

O que isso tem a ver com a sua missão

Na próxima missão (M0.7) você vai usar um modelo pronto, que outra pessoa já treinou com muitas frases rotuladas como positivas, negativas ou neutras. Você não vai treinar nada: só vai pedir previsões para frases suas e anotar onde ele erra. Quando ele errar, lembre-se da mensagem do salário.

Daqui a 18 meses, o seu trabalho vai ser fazer o caminho inteiro: juntar os dados, treinar, medir os erros e colocar o modelo no ar para outras pessoas usarem.
