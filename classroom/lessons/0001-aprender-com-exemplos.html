Aprender com exemplos

Hoje você vai entender a ideia que está por trás de tudo o que vai estudar nos próximos 18 meses. Sem código, sem matemática.

Você já usa isso todo dia

O filtro de spam do seu e-mail, a sugestão de palavra do teclado do celular, o “talvez você goste” da Netflix. Ninguém escreveu à mão uma regra para cada mensagem, cada palavra ou cada filme. Esses programas aprenderam olhando muitos exemplos.

Isso é Machine Learning (em português, aprendizado de máquina).

A ideia numa frase

Machine Learning é treinar um programa, chamado modelo, para fazer previsões úteis a partir de dados.

Tradução livre da definição do curso de ML do Google.

A diferença para a programação comum está em quem escreve as regras:

Programação comum Regras (uma pessoa escreve) + dados → Programa → Respostas
Machine Learning Dados + respostas → Treino → Modelo (as regras)

Em vez de alguém escrever as regras, você dá ao computador exemplos com a resposta certa, e ele descobre sozinho o padrão. Quem marca as respostas certas funciona como um “supervisor”. (Elements of AI, cap. 4.1)

O que acabou de acontecer

Você não recebeu nenhuma regra. Olhou exemplos com resposta e montou uma regra na cabeça, algo como “promete dinheiro → spam”. Depois usou essa regra em mensagens que nunca tinha visto. Foi isso que você fez, com os nomes que vai usar daqui em diante:

Dados
os exemplos (as 6 mensagens).
Rótulo
a resposta certa de cada exemplo (spam ou não spam).
Treino
olhar os exemplos e descobrir o padrão.
Modelo
a regra descoberta no treino.
Previsão
a resposta do modelo para um caso novo.

Nomes usados também no curso do Google (em inglês: dataset, label, training, model, prediction).

Duas coisas para guardar

  1. ML vale a pena quando a regra é difícil de escrever. Prever chuva com equações da física é dificílimo; dar ao modelo muitos dados de clima e deixar que ele aprenda a relação é mais viável. (Google) Se a regra é simples e conhecida, como uma tabela de imposto, é só escrever a regra.
  2. O modelo só sabe o que os exemplos mostraram. Exemplos ruins ou incompletos geram um modelo que erra, como a mensagem do salário mostrou. Por isso, boa parte do trabalho de um ML Engineer é cuidar dos dados e medir onde o modelo erra.

Onde isso encontra a sua missão

Na próxima missão (M0.7) você vai usar um modelo pronto, que alguém já treinou com muitas frases rotuladas como positivas, negativas ou neutras. Você não vai treinar nada: só vai pedir previsões para frases suas e anotar onde ele erra. Quando ele errar, lembre da mensagem do salário.

Em 18 meses, o seu trabalho vai ser o caminho inteiro: juntar os dados, treinar, medir os erros e colocar o modelo no ar para outras pessoas usarem.
